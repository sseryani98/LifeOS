---
name: review-gotchas
description: Mechanical traps that produce wrong citations or wrong coverage conclusions when reviewing Project Tracker specs
metadata:
  type: reference
---

- `cat -n a b` numbers lines continuously across files. Print one file per `cat -n`, or confirm anchors with `grep -n "  it("`, before citing a line. (2026-11-02: readPath.test.ts read after projectView.test.ts was offset by 175.)
- `*Facade.ts` is excluded from coverage, so "100% on trackerService" hides untested facade branches. Example: `_handleReadMilestones` / `_handleReadProjectView` wrap a single-object result (a by-key GET) into an array, and no spec does a by-key read.
- The unit tier never loads `@sap/cds`, so `SELECT` is not a global there. A mutation that drops a "skip the count" guard in `trackerService` crashes with ReferenceError rather than failing an assertion. It is still caught, so it is not a finding by itself.
- PT has no app/, so `lint:i18n` scans 0 files and dead `messages.properties` keys go unchecked. Loop each key through `grep -rF` over srv/ mcp/ test/ (2026-11-03: all live, but it is the only check).
- Test-support headers that claim "no suite inserts/clears X" drift when a sibling helper starts mutating X. Grep `INSERT.into|DELETE.from` over test/ (2026-11-03: seedWorld.ts TABLE comment vs libraryAccess.ts).
- Annotation hunts: `@cap-js/db-service` `fill-in-keys.js` fills a missing cuid `ID` on a plain `INSERT.into(X).entries(rows)` (skipped only for `.rows`/`.values`), so `randomUUID()` for a row nobody else references is Redundant. A key another row's FK needs (Task ID → Subtask.task_ID over an Association, which gets no deep insert) is Justified. Fast probe: scratchpad CAP project, sqlite `:memory:`, `NODE_PATH="C:/Projects/Life OS/node_modules" node probe.js`, with a control row.
- Annotation hunts: `@mandatory` fires on **`function`** params too (not just actions) at 9.8.4 — omitted/null → 400 `ASSERT_MANDATORY`, target = param; un-annotated control passes `undefined`, and `SELECT.one.where({ID: undefined})` returns undefined, so a not-found guard misreports a missing id as 404. Probe: `cds.serve('S').from(csn)` + `S.send(fn, {})` in plain node (2026-11-04, FP suggestRecurringSplit).
- Annotation hunts, after-READ sort/cap handlers: at 9.8.4 (sqlite probe, 2026-11-05) `order by x desc` on a service projection holds both top-level and through a parent `$expand`, but `@cds.query.limit: {default, max}` clamps only top-level reads. It does not cap a `$expand`ed collection or `$count`, and `$skip` still pages past it. A JS cap on an expanded section is therefore Justified; a JS sort on a column the view already exposes is Missed. Probe server: `cds.serve('all').in(express())` + `fetch`.
- Row types in `mcp/verbs/shared/types.ts` get fields made optional (`requiresHuman?`, `driver?`) so old unit fixtures still compile, even though the schema says `not null` and the gateway always selects them. On a guard flag that is fail-open. Diff `types.ts` against `db/schema.cds` and the fixture file. (2026-11-03, SPEC-02.)
- Specs carry structural mandates you can cite. SPEC-02 §6 OI-05 says the blocking "predicate is named rather than inlined", and §4 BR-30 fixes guard order. Grep the spec's BR and OI lines before arguing duplication from taste. The spec's error table (SPEC-03 §5) names per-rule keys too: `MigrationValidator` re-checks Defect/TestRun scope that TrackerService's before-write guards also enforce, because the spec wants `cnv.*` keys. That makes it a Justified p re-check, not Redundant.
- Duplication review: srv/ and mcp/ guard the same rules under twin constants (`HANDLER_KEYS.X` and `VERB_KEYS.X`, same string). Grep the key *value* across both when a diff changes a srv guard. A verb pre-check outside the diff can turn redundant that way; 2026-11-03 SPEC-02 made `planSprint._assertStoryIdsFree` duplicate `checkMilestoneWrite`. Same for non-key constants: grep every new string value in `srv/modules/shared/constants.ts` against `mcp/verbs/shared/constants.ts` (2026-11-05 SPEC-04: `REFERENCE` = `ADDRESSING`, `NEXT_ACTION.COMPLETION_EVENT_KIND` = `ACTIVITY_KINDS.STAGE_COMPLETED`; the hoist precedent is `FRICEW_TYPES = CODES.FRICEW_TYPES`). Also: the gateway reads through `ctx.service`, so srv after-READ handlers fire on verb reads — a verb/gateway re-sort of a handler-ordered entity is a twin. Same for plain values: grep each new `srv/modules/shared/constants.ts` literal in `mcp/verbs/shared/constants.ts` (SPEC-04: `REFERENCE` twinned `ADDRESSING`, `COMPLETION_EVENT_KIND` twinned `ACTIVITY_KINDS.STAGE_COMPLETED`). mcp already imports srv `CODES`, so the single-source fix is the `FRICEW_TYPES = CODES.FRICEW_TYPES` alias.
- The `code-review` skill runs forked and has StructuredOutput in its toolset, so it can submit its own findings there and hand the parent only "Skill execution completed" with no text. In that case the findings cannot be recovered, so return `[]` and do not reconstruct them yourself. (2026-11-03, SPEC-02 code-quality run.)
- Guards that judge only the payload on UPDATE are a known defect pattern here. Initiative and Milestone merge the stored row; Defect does not, and TestRun has no UPDATE guard. Check each new entity guard for both.
- TDD-red scaffolds outlive the red phase. A test-support loader that `require`s by computed path and casts to a caller-written contract (`test/shared/support/migrationModule.ts` `loadMigrationExport`, SPEC-03) keeps its "type-checks before the domain exists" header once the domain is green, and the hand-written contract silently stops tracking the real class. Grep `require(join(` in test/support. FP variant: a support helper that casts a real instance `as unknown as { newMethod: ... }` plus a re-declared DTO interface (FP transactionMocks.ts `suggestRecurringSplitOn`, 2026-11-04) — grep `as unknown as {` in support/ and check whether the class now has the method.
- Comments on a multi-step runner that say a later step "catches" an earlier failure: check whether the throw skips that step and whether a rerun is refused upstream (SPEC-03 `migrateFinancialPlanner.ts` runMigration JSDoc vs per-conversion `tx` + `ALREADY_LOADED`).
- Duplication review, spec-mandated twins: SPEC-03 §5 names its own keys (`cnv.defect.targetMissing`, `cnv.testrun.targetMissing`) for rules TrackerValidator already guards under `tracker.*.scopeRequired`, so MigrationValidator's twin checks are by design. Read the spec's Error Handling table before reporting a validator as a copy.
- Red-phase scaffolding outlives green: test-author loads not-yet-written source through a computed-path `require` (`test/shared/support/migrationModule.ts`), which forces hand-copied contract interfaces in support files. Once the source exists, those copies duplicate `srv/.../types.ts` and stop failing `tsc` on drift. Grep `loadMigrationExport`/`require(join(` on every post-build review. UI5 variant: `test/support/types.ts` re-declares model DTOs plus a `XxxSource` cast interface for a method the class lacked at red, and OData fakes hedge on API shape (`execute`, `requestObject`, inline-path regex) the green code never calls (FP transactions, 2026-11-04). Diff support types against `model/types.ts`.
- UI5 `*.qunit.ts` specs carry spec-local arrow helpers (`useFreshX`, `readXModel`, `selectX`) in every FP app, and `lint:test-data` passes them. Treat that as the accepted pattern; flag only a helper that is a *stub builder* (a fake event or object cast `as unknown as`), which belongs in `support/`. (2026-11-04, shell App.qunit.ts `buildItemSelect`.)
- Fixture-map doc comments that say "as X declares them" drift when the map gains a deliberate negative key (`NAV_KEY.UNREGISTERED` in shell `test/data/constants.ts`). Check each key against the source it claims to mirror.
- UI5 OData fakes that resolve `undefined` for an unstubbed path (`buildFakeODataModel` in csv-import-wizard `test/support/odataModelFakes.ts`) let a "cannot be read" test pass against a service with no `catch`. A real V4 `requestObject()` rejects on 404. Grep the service for `catch` before trusting any fake-backed "tolerates a failed read" test. (2026-11-04, `CsvImportWizardService._loadTransaction`.)
- An after-READ handler that sorts/ranks/caps `rows` only sees the page the DB returned. An FE `macros:Table` always sends `$top` (growing), so with no `PresentationVariant.SortOrder` the DB page is arbitrary and the handler orders the wrong subset. Integration specs read via `$expand=x` with no `$top`, so they never see it. Check the entity's annotations file for SortOrder and whether the spec ever pages. (2026-11-05, PT `ProjectViewService.applyQueueDerivations`, `taskQueueItems.cds` "No SortOrder" carve-out.)
- XML-view expression bindings that map a code to an i18n label (`${kindCode} === 'Recommended' ? ${i18n>kindRecommended} : …`) pass every lint, yet re-implement a CodeList's `name` and get copy-pasted per control. Grep the view for repeated `=== '` ternaries and check `db/reference/schema.cds` for the CodeList behind the code. (2026-11-05, PT project-view `ProjectView.view.xml` StepKind/TaskStatus.)
