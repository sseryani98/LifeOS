Checks that caught real defects in a test-quality review (ingestion, 2026-11-02). Apply to every module.

- **Key-insensitive reference mocks.** `support/*Mocks.ts` often stubs a lookup as `jest.fn(async () => SOME_ID)` ignoring its argument (e.g. `getAlertTypeId` in `test/unit/ingestion/support/simplefinMocks.ts`). Any `toHaveBeenCalledWith({ alertType_ID: SOME_ID })` is then meaningless — there it even asserted the "Connection Error" seed id on an unmapped-account alert. Grep mocks for lookups that ignore their key. UI5 fakes too: `app/shared/test/support/sharedFakes.ts` `findElements: () => elements` ignores the `true` (deep) flag, so dropping it in `ObjectPageParser` survives. Also check a fake handing out one fixed instance (single dialog id per host) — it hides per-key caching bugs when the real caller (TransactionActions) uses two keys.
- **Fixture leaks from tracked real exports.** `Financial Planner/design/actual-csvs/*.csv` (real bank exports) is git-tracked. Fixtures "trimmed from the real exports" copy identifiers verbatim — `test/shared/data/ingestion/csv.ts` carried a real masked PAN. Grep fixture strings against `design/actual-csvs/`.
- **Chained integration specs.** Look for a test with no Act, or comments like "created by the prior test" — `simpleFinSync.test.ts` and `csvImportSave.test.ts` chained state across `it`s, breaching TEST_STRATEGY §6.3. Storyline chains are only allowed under `integration/scenarios/` (§6.4).
- **Fixtures that satisfy every clause of an OR.** A "pending" fixture with both `pending:true` and `posted:0` hides `||`→`&&`. Similarly a "most-frequent vendor" fixture with one vendor hides a first-seen mutation. Check that each guard clause gets its own fixture.
- **Mappers covered 100% but never asserted.** Coverage can come entirely through a Service test whose `toMatchObject` skips the mapped scalars (amount, dates). When a mapper has no spec of its own, check which of its output fields any assertion actually reads.
- **Dead keys in test `data/` key maps; twin table-name maps in `support/`.** No linter checks a data export's *members* are used. PT SPEC-03 `integration/migration/data/financialPlannerSnapshot.ts` `MIGRATION_KEYS` held 5 keys only the unit tier tests (with its own copy); `TABLE` was copied verbatim in `readMigration.ts` + `tamperReconciled.ts` because support/ may not export data. Grep each key across `test/`.
- **"Output is a prefix of input" assertions are blind to cutting earlier.** PT SPEC-03 `registers.test.ts` checks each Defect title is a non-empty prefix of its description; dropping `DefectTitle`'s code-span rule or a clause end still yields a prefix. A derivation needs exact expected values for the rows that hit each rule (pure class → unit test).

- **Declared-but-unasserted refusal keys = an untested refusal path.** Grep each key in a test `data/` `*_KEYS` map for a `toBe(KEY)`/`toContain(KEY)` in a spec. PT SPEC-03 (2026-11-04): `DEFECT_TARGET_MISSING`/`TEST_RUN_TARGET_MISSING` sat in data, never asserted, so `seedRegisters`' pre-write validation was proven only by the unit Validator test; `ORDERING_MISMATCH` was absent from data entirely and its finding could return `[]` with all green.
- **Decimal-as-string coercion is never exercised.** Jest runs SQLite, which returns `Decimal` as numbers; Postgres returns strings. A mapper whose type says "possibly as strings" (FP `TransactionMapper.toRecurringSplitTemplate`, 2026-11-04) is proven only with numeric fixtures, so dropping its `Number()` survives. Look for a direct mapper test fed `"22.00"`-style input.
- **Append-vs-replace survives when the target starts empty.** A handler that does `setProperty(path, [...existing, item])` / `filter(r => r.key !== x)` is only proven if the spec seeds `existing` non-empty and a second sibling. `csv-import-wizard` `CsvImportWizard.qunit.ts` excluded-row moves seeded empty `/newRows` and one excluded row, so wiping the user's reviewed rows passed green. Grep spread-append writes in UI5 controllers.
- **Either/or input resolvers: enumerate the quadrants.** FP `SplitTerms.resolveShares` (pct vs amount, seeded vs edited) had tests only for untouched-suggestion and single-field entry, so `pct !== null ? null : amount` survived all green. Ask for the both-entered and edited-one-of-seeded-pair cases.
- **Script entry points are invisible in the coverage table** unless a test imports them — a missing row is 0%, not excluded. Check `scripts/*.ts` against `test/script/`.
- **A cold branch in an async-callback cache is usually a race bug, not a nit.** FP shell `App.controller.ts` 119-125 (UI5 93.1% branches): one `_pendingRoute` field shared by every lazily-created `ComponentContainer`, never updated when a container is reused before `componentCreated` fires. Write the "second select before the first component exists" test — it is red today.
- **UI5: a controller field cached from a selection event survives at 100% coverage.** FP `ConnectionManager.controller.ts` `_selectedConnection`: the clear-selection test asserts the view binding + `ui>/hasSelection`, the Sync Now no-op test uses a never-selected page — so "keep the stale context on clear" mutates green. Always ask for select → clear → act.
- **UI5: prototype-stubbing a model/ service hides the controller→service wiring.** When `{App}Service.prototype` methods are replaced, the model `onInit` hands the service is never read; `new Service(view.getModel("ui"))` passes. Check one test reads `controller["_service"]["_model"]`.
- **The tree may churn mid-review** (parallel agents/formatters). Before reporting a data↔assertion mismatch, `ls --time-style=full-iso` the files; a seconds-old mtime means it is in flux — drop it.

**Why:** these are judgment-layer gaps that coverage and the lint suite report as green.
**How to apply:** run these greps first in any test-quality pass, before reading tests one by one.

- **`as unknown as { method }` contracts outlive red phase in both tiers.** FP transaction 2026-11-04: `suggestRecurringSplitOn` (unit mocks), `suggestRecurringSplitFor` (integration support), and UI5 `RecurringSplitSource` in `app/transactions/webapp/test/support/types.ts` all cast to a hand-written copy of a method that now exists (copy already drifted: `splitDescription: string` vs real `string | null`). Grep `as unknown as {` and `as unknown as Recurring|Source` in support/ on every post-build review.
