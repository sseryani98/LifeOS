NameModelPurpose
build-briefersonnetRead-only story resolver for the build workflow. Turns a story ID in any module into a structured brief by extracting from the design docs. Cannot write, cannot run commands, cannot decide anything the docs do not already say.
doc-writeropusTurns a completed stage record into that stage's design document — a spec, FRICEW catalogue, vision, information architecture, design system, theme, data model, tech stack, test strategy, build plan or module CLAUDE.md — following the stage's template and its skill's writer brief exactly, and validating the result before returning. Writes in an isolated context so producing a large document never competes with the interview that settled it. Does not interview; if the record has a hole, it returns a gap rather than inventing.
domain-scoutopusReads a module's vision doc, PRD, and source material and returns a classified FRICEW candidate inventory — every candidate with a file:line, a proposed type, and a scope classification. Runs in an isolated context so a large source doc never floods the scoping interview. Classifies; does not decide scope.
functional-testersonnetRuns a story's Functional Unit Tests end-to-end against the running app — through the browser, the OData service or the MCP verb server, whichever the FUT drives — on a throwaway Postgres database, then probes around each one for integrity, validation and bug findings. Reports a pass/fail matrix. Read-only against the tree — it verifies, it never fixes.
gate-runnerhaikuRuns the build gate (tsc, lint, test, cds build) and reports raw results. Classifies each failure so the workflow can route repair to the right model tier. Never fixes anything.
implementeropusBuilds the source for a story until the gate is green, working against tests it may not edit. Also marks the sprint board at handoff. Never commits.
quality-revieweropusRead-only code reviewer for the code-quality workflow. Finds judgment defects and argues about them, but cannot modify the tree. Use for any review stage that must not apply its own findings.
research-scoutopusResearches one topic to a verdict and writes its document in the module's research/ pack — working documentation-first, tiering every claim by evidence quality, and reporting what it could not establish as carefully as what it could. Runs in an isolated context so many topics can be researched in parallel without any raw source page reaching the main thread. Returns a findings card, not prose. Does not design, and never upgrades a weak verdict to a confident one.
smoke-testersonnetDrives a built UI in a real browser and reports what it observed. Read-only against the tree — it validates, it never fixes.
test-authoropusWrites the failing tests for a story from its business rules and FUTs, and later raises coverage to threshold. Owns the test tree and writes nothing outside it.
ux-testersonnetReviews a story's built pages against the Design System, Theme, and Information Architecture in a real browser — contrast, theme adherence, wording, and page-to-page consistency. Read-only against the tree; it reports, it never fixes.
