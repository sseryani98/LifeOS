## 3. Scope Boundary

This catalogue covers slice 1 of Project Tracker as stated in
[PSV-001 §6](PROBLEM_STATEMENT_AND_VISION.md) — the seven hierarchy entities, Methodology +
MethodologyStep, the registers, the Financial-Planner-only migration, the MCP intent-verb access
layer with its rewiring surface, and the project view — cut from `PRD.md` (the full product design,
of which slice 1 is a small fraction) and from `PLAN.md` §5–6. Every PSV §7.1 deferred cluster is
recorded below and catalogued nowhere else.

### 3.1 Traceability anchors and PRD provenance

Objects trace to PSV problems **P1–P5**, decisions **D-01…D-32**, open items **OI-01…OI-05**, and
sibling FRICEW IDs. They do **not** trace to PRD sections. The PRD carries no stable IDs, no version
block and no decision IDs; it predates D-04, D-05, D-08, D-10 and D-11 and describes a human-UI
product. It also has **zero coverage of three of the six slice-1 items** — the MCP layer, the
migration, and TestRun: a grep of the full 1490-line file finds no occurrence of MCP, agent, verb,
migration, TestRun, gate-runner, sprint or story. The PRD is therefore cited as a source anchor for
deferred items only, never as a trace anchor for an object.

### 3.2 P2 is knowingly unserved

PSV problem **P2** (Sandro's project universe is fragmented) has **no object in this catalogue**.
That is D-11 executing as written — v1 serves Financial Planner and only Financial Planner — not an
omission. The consequence: PSV §4 falsifiable check 6 ("a second project onboards requiring no new
tracking system") **cannot be evaluated until a later slice**. P1, P3, P4 and P5 are each served by
multiple objects.

### 3.3 ID collision hazard — Project Tracker IDs are not Financial Planner IDs

Story ID sequences are module-local. Project Tracker's **CNV-001** (Methodology Library Seed) is
**not** Financial Planner's **CNV-001** (Historical Transaction Backfill). D-13, PSV-001 §4 and
`PLAN.md` all say "cutover before CNV-001" meaning **Financial Planner's** story, not this
catalogue's object. The same hazard applies to `INT-001`, `INT-002`, `ENH-001` and `FRM-001`, which
exist as story IDs on both modules' boards. Every reference below to a Financial Planner story ID is
written with the module name attached; an unqualified ID always means this catalogue.

### 3.8 Handed to another stage — not deferred

The **32 residual retired-path references** across six `Financial Planner/design/*.md` files
(TEST_STRATEGY 7, BUILD_PLAN 7, PROJECT_MANAGEMENT 7, VERSION_CONTROL 5, TECH_STACK 4,
user-profile/DECISIONS_LOG 2) go to a `/refresh-docs` sweep at cutover rather than becoming
catalogued objects (D-23). `PROJECT_MANAGEMENT.md` and `BUILD_PLAN.md` are the most instruction-like
of the six — if `lintNoMarkdownState`'s glob ever widens to `Financial Planner/design/**`, they
become build work.

**OI-01 durability** was recorded here as an uncatalogued sequencing constraint blocking CNV-005
(D-27). **D-31 resolved it and D-27's own amendment trigger fired**: the answer is a `pg_dump -Fc`
runbook plus a built CSV exporter committed to git, catalogued as **INT-007**. Per the research
pack's caveat it is an **Interface, not a Conversion** — a recurring exporter catalogued as `CNV`
would land inside §5's strict `CNV-001 → … → CNV-005` execution chain, where it does not belong, so
D-27's pre-labelling is superseded. CNV-005 is no longer blocked on an open item; it depends on
INT-007.

### 3.9 This stage has no linter

`/pm-update` check 3 validates the board against this catalogue, but **nothing mechanically
validates the catalogue's own ID sequence, prefix enum or trace completeness**. The coverage check
behind this document is procedural, not enforced. A shared `lint:fricew-catalogue` in
`Standards (Technical + Linting)/scripts/` is the obvious follow-up once a second module has proved
the rules.

### 3.10 Resolved by the Research stage

**OI-01 and OI-02 were both open when v1.0 was written and are now closed.** OI-02 is settled by
**D-29** (two CDS models, separate Postgres databases) together with **D-30** (one shared UI5 shell,
which needs one origin rather than one service and therefore composes with D-29); OI-01 is settled by
**D-31** (a `pg_dump -Fc` runbook plus INT-007's CSV exporter, destined for a git remote this repo
does not yet have). **OI-04** (what calculated health computes) and **OI-05** (how generic
`Methodology` must be) remain open, at the ENH-003 workshop and the Data Model stage respectively;
both were deliberately excluded from the research wave because neither is a fact to discover.

**Five risks stay live and unexecuted**, and none of them is a catalogued object: **R1** — the
validating spike ran on in-memory SQLite, so Postgres is unproven; **R2** — how a TypeScript service
implementation loads outside `cds watch`, the **highest-priority residual** and a Tech Stack decision
rather than build work; **R7** — the CSV round-trip is untested; **R9** — two CAP processes serving
into one shell page is `Inferred` only; **R10** — the installed Claude Code is v2.1.90 against
documentation read to v2.1.218. The full risk table and what would settle each is
[`research/README.md` §5](../research/README.md) and is not restated here.

catalogue's.

shared shell requires one **origin**, not one service, so it composes with D-29's two models rather
than contradicting them. Financial Planner's existing hand-built `app/shell` — a `sap.tnt.ToolPage`
hosting four apps as components — proves the single-module case; risk **R9** is live and `Inferred`
only, since two CAP processes serving into one shell page has never been executed. Settle it with a
second server on another port, one resource root, and both components in one host page.

### Dependency notes

- **Longest chain (7 deep):** CNV-001 → ENH-001 → CNV-004 → WFL-001 → RPT-003 → INT-002 → CNV-005.
  It runs through all three waves, so it sets the critical path.
- **Widest fan-in:** CNV-005, which cannot run until all **six** other Interfaces objects are
  complete — every consumer must be off markdown before the markdown goes, and INT-007 must exist
  before the diffable form of state is retired with it.
- **Widest fan-out:** INT-001, which every wave-2 and wave-3 object depends on. It is the first thing
  built and the thing most expensive to get wrong.
- **Sequencing constraint from D-07:** INT-006's two guards are built in wave 3 but must not be
  _enabled_ until CNV-005 — enabling either while markdown is still authoritative would hard-deny
  legitimate Financial Planner work.
- **External blocker resolved:** CNV-005's **OI-01** blocker is closed by D-31, and what was an open
  item is now an in-catalogue dependency on **INT-007**. That is why INT-007 sits in wave 3 rather
  than later — it must exist before CNV-005 retires the markdown.
