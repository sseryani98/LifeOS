## 3. Scope Boundary

This catalogue covers slice 1 of Project Tracker as stated in
[PSV-001 §6](PROBLEM_STATEMENT_AND_VISION.md) — the seven hierarchy entities, Methodology +
MethodologyStep, the registers, the Financial-Planner-only migration, the MCP intent-verb access
layer with its rewiring surface, and the project view — cut from `PRD.md` (the full product design,
of which slice 1 is a small fraction) and from `PLAN.md` §5–6. Every PSV §7.1 deferred cluster is
recorded below and catalogued nowhere else.

### 3.1 Traceability anchors and PRD provenance

Objects trace to PSV problems **P1–P5**, decisions **D-01…D-32**, open items **OI-01…OI-05**, and
sibling FRICEW IDs. They do **not** trace to PRD sections. The PRD carries no stable IDs, no version
block and no decision IDs; it predates D-04, D-05, D-08, D-10 and D-11 and describes a human-UI
product. It also has **zero coverage of three of the six slice-1 items** — the MCP layer, the
migration, and TestRun: a grep of the full 1490-line file finds no occurrence of MCP, agent, verb,
migration, TestRun, gate-runner, sprint or story. The PRD is therefore cited as a source anchor for
deferred items only, never as a trace anchor for an object.

### 3.2 P2 is knowingly unserved

PSV problem **P2** (Sandro's project universe is fragmented) has **no object in this catalogue**.
That is D-11 executing as written — v1 serves Financial Planner and only Financial Planner — not an
omission. The consequence: PSV §4 falsifiable check 6 ("a second project onboards requiring no new
tracking system") **cannot be evaluated until a later slice**. P1, P3, P4 and P5 are each served by
multiple objects.

### 3.3 ID collision hazard — Project Tracker IDs are not Financial Planner IDs

Story ID sequences are module-local. Project Tracker's **CNV-001** (Methodology Library Seed) is
**not** Financial Planner's **CNV-001** (Historical Transaction Backfill). D-13, PSV-001 §4 and
`PLAN.md` all say "cutover before CNV-001" meaning **Financial Planner's** story, not this
catalogue's object. The same hazard applies to `INT-001`, `INT-002`, `ENH-001` and `FRM-001`, which
exist as story IDs on both modules' boards. Every reference below to a Financial Planner story ID is
written with the module name attached; an unqualified ID always means this catalogue.

### 3.9 This stage has no linter

`/pm-update` check 3 validates the board against this catalogue, but **nothing mechanically
validates the catalogue's own ID sequence, prefix enum or trace completeness**. The coverage check
behind this document is procedural, not enforced. A shared `lint:fricew-catalogue` in
`Standards (Technical + Linting)/scripts/` is the obvious follow-up once a second module has proved
the rules.

### 11.1 The contested cut — SPEC-01 and WFL-001

`complete_stage`'s failure modes _are_ WFL-001's rejections, which is a real argument for merging
SPEC-01 and SPEC-02. They stay split because the seam is clean and §4 of this document already drew
it: **INT-001 specifies _that_ a rejection surfaces as a typed MCP error; WFL-001 specifies _which_
rejections exist.** Splitting also unblocks the widest fan-out object in one session rather than
four. If SPEC-02's workshop finds the seam leaking — a guard that cannot be stated without changing
INT-001's verb signature — that is the trigger to amend D-37, not to patch it quietly.

**Tested at the SPEC-02 workshop, 2026-07-27 — the trigger did not fire (D-55).** Every guard in
SPEC-02 is decided from `story`, `stage`, `subtask`, `reason` and the caller identity INT-001 already
carries under D-41, so none required a new or changed verb input and **D-37 stands unamended**. The
seam held in a stronger form than this section anticipated: SPEC-01's `verb.stage.blocked` is the
**envelope** code and SPEC-02's `wfl.*` keys are the specific rules inside it, which is exactly
"INT-001 says _that_ a rejection surfaces, WFL-001 says _which_ rejections exist" expressed in the
i18n key space. Recorded because a tested-and-held trigger is a finding — the next reader would
otherwise not know it had been checked.
